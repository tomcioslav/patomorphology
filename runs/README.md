# Runs

Each subdirectory is one training execution. Layout:

```
runs/
└── <run_name>/
    ├── config.yaml          # the RunConfig that produced this run
    ├── checkpoints/
    │   ├── last.ckpt        # most recent epoch
    │   └── best-*.ckpt      # best by val_loss
    ├── tensorboard/         # event files (one set per run)
    └── samples/             # optional: prediction dumps for review
```

`<run_name>` convention: `{pipeline}-{source}-{YYYYMMDD-HHMMSS}` —
e.g. `unet-nmsc5x-20260507-094215`. Auto-generated by the pipeline's
`train()` unless overridden.

## Loading a run

```python
from config import paths
from pato.experiments import list_runs, load_run, load_predictor

list_runs(paths.runs)
# ['unet-nmsc5x-20260507-094215', ...]

run = load_run(paths.runs / "unet-nmsc5x-20260507-094215")
run.best_checkpoint()       # → Path
run.config                  # → dict (hparams, source, etc.)

predictor = load_predictor(paths.runs / "unet-nmsc5x-20260507-094215")
mask = predictor.predict("data/raw/.../some_image.tif")
```

`load_predictor` reads `config.yaml`, sees `pipeline: unet`, and
instantiates the right `Predictor` subclass.

## Why a folder per run

- Everything for that experiment lives together — config + weights + logs.
- Easy to delete a bad run (just `rm -rf runs/<name>/`).
- Easy to share or archive a run (zip the folder).
- `tensorboard --logdir runs/` aggregates **all** runs in one UI.
